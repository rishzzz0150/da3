# 🎮 Esports Tournament Management System

A database-driven web application for managing esports tournaments, teams, players, matches, tournament stages, match officials, prize pools, sponsors, and performance analytics.

The project demonstrates how database management concepts can be applied to a real-world esports organization through a web-based dashboard built with Flask and CockroachDB.

## 📌 Project Overview

Esports tournaments involve multiple games, professional teams, registered players, tournament administrators, referees, sponsors, and competitive stages. Managing this information efficiently requires a well-structured relational database.

The **Esports Tournament Management System** provides a centralized platform to organize tournament data, manage records, monitor match progress, analyze team performance, and generate reports using SQL operations.

The application combines a Python backend, a web-based frontend, and a CockroachDB database.

## 🗄️ Database Design

The database is designed around the entities and relationships required to manage an esports tournament organization.

The schema includes tables for:

- **Games and Tournaments:** `games`, `tournaments`, `tournament_stages`
- **Teams and Personnel:** `teams`, `players`, `coaches`, `analysts`, `team_managers`
- **Tournament Operations:** `administrators`, `referees`, `matches`, `match_officials`
- **Statistics and Monitoring:** `match_statistics`, `gameplay_analytics`, `anti_cheat_monitoring`
- **Equipment:** `equipment`, `player_equipment`
- **Discipline:** `disciplinary_actions`
- **Sponsorship and Finance:** `sponsors`, `tournament_sponsors`, `prize_pools`, `financial_records`
- **Streaming and Audience Engagement:** `streaming_platforms`, `match_streams`, `audience_votes`
- **Rankings and Recognition:** `tournament_rankings`, `awards`

The schema uses relational keys and constraints to maintain data integrity. Exact table and column definitions are available in the project's database.

## 🧠 DBMS Concepts Demonstrated

This project applies several fundamental database management concepts:

- **Relational database design:** organizing tournament information into related tables.
- **Primary and foreign keys:** identifying records and maintaining relationships.
- **CRUD operations:** creating, reading, updating, and deleting records.
- **JOIN operations:** combining related data, such as teams and match results.
- **Aggregate functions:** using `COUNT`, `SUM`, `AVG`, `MIN`, and `MAX`.
- **GROUP BY and ORDER BY:** summarizing and ranking data.
- **Filtering:** retrieving records that satisfy specified conditions.
- **Parameterized queries:** safely passing user-provided values to SQL statements.
- **Database constraints:** protecting relationships between records.

## ⚙️ Installation and Setup

### Prerequisites

Install the following before running the application:

- Python 3.10 or a compatible newer version
- Git
- A CockroachDB database or cluster with the project schema created
- Visual Studio Code or another Python-compatible editor (optional)

### 1. Clone the repository

Replace `YOUR-USERNAME` and `YOUR-REPOSITORY` with your GitHub details.

```bash
git clone https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
cd YOUR-REPOSITORY
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Activate it on Windows PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, you can run the Python executable inside the virtual environment directly instead.

### 3. Install dependencies

```bash
python -m pip install -r requirements.txt
```

### 4. Configure the database connection

Set the `DATABASE_URL` environment variable to your CockroachDB connection string.

For Windows PowerShell:

```powershell
$env:DATABASE_URL="YOUR_COCKROACHDB_CONNECTION_URL"
```

Replace the placeholder with your actual connection URL. Keep your database username, password, and connection details private.

The connection URL must contain the database name and the connection parameters required by your CockroachDB cluster.

**Important:** Set this variable in the same terminal used to start Flask. Do not commit your real credentials to GitHub.

### 5. Start the application

```bash
python app.py
```

### 6. Open the dashboard

Visit the following address in your browser:

http://127.0.0.1:5000

The application should display the dashboard if the database connection is configured correctly and the required schema is available.

## 🔐 Security Notes

- Never commit database passwords, access tokens, or private connection strings.
- Store connection details in environment variables.
- Keep `.env` files and other secret files out of Git.
- Use parameterized SQL for user-supplied values.
- Validate table and column selections before constructing database queries.
- Restrict database permissions to the operations required by the application.
- Before public deployment, configure production settings, disable Flask debug mode, and review access controls.
